# QB-30 — Production cutover and post-cutover integrity verification

**Status: DONE (the cutover runbook is a script, the gate is explicit, and the rehearsal passed 18/18).**
`scripts/qb30-cutover.ps1` performs the cutover in the order of the specification §6.1 and stops at the
first failed gate. It never starts without the business owner's codeword, it never deletes anything, and it
never rolls back to the legacy database - a failed gate means *stop and fix forward*, with the legacy data
left read-only.

## What the cutover does

| Step | What it verifies or performs |
|---|---|
| 0. the codeword gate | The script refuses to start unless the codeword matches the expected one. A cutover is never an accident. |
| 1. the final backup | A fresh `pg_dump` with its SHA-256 manifest, written before anything else. |
| 2. the schema and the health | The server starts, the health endpoint answers and **no PostgreSQL migration is pending**. |
| 3. the final frozen import | The frozen snapshot is imported again (idempotent: the same rows are updated, nothing is duplicated) and the **signed** reconciliation report is produced. Every exception must be approved (an approvals list) - an unapproved exception blocks the go-live. |
| 4. identities and devices | The reset flow is exercised end to end (request → complete), because the import never carries a credential, and the desktop device is enrolled for the business and location. |
| 5. the smoke | A sign-in, the balance sheet (which reads the authoritative ledger) and the read-only master data. |
| 6. the integrity verification | The posted ledger balances (debits = credits), the stock movements tie to the balances, no business row is unowned, the invoice numbers are unique per business, the posted sales equal the confirmed payments, and no tracked legacy project file remains (no live WinForms dependency). |
| 7. the checklist and the handover | The go/no-go checklist, the stop/fix-forward plan and the evidence are printed and kept. |

## The stop/fix-forward plan

- **Stop**: a failed gate means the legacy system stays read-only, the new system does not open for writes
  and nothing is deleted.
- **Forward**: fix the gate, re-run the import (it updates the same rows), re-run the script.
- **Never**: a blind rollback to the legacy database and a destructive purge of the legacy backups.

## Decisions recorded

- **D-57** — the cutover gate (QB-30): the cutover is a script with an explicit go/no-go checklist, not
  a checklist of steps. It requires the business owner's codeword, takes a verified backup before it
  touches anything, re-runs the (idempotent) frozen import, refuses to continue while a reconciliation
  exception is unapproved, verifies the posted ledger, the stock, the tenant ownership and the invoice
  numbering, and prints the stop/fix-forward plan with the handover record. It never deletes and never
  rolls back to the legacy database.
