# QB-27 — Operational runbooks, backup, packaging and observability

**Status: DONE (runbooks, packaging configuration, observability).** The day-2 operations are written down
where an operator will actually look for them: `docs/migration/deployment.md` now carries the deployment,
backup, restore, credential rotation, device loss, device reset, stuck queue, failed migration and disk-full
procedures, the packaging (unpackaged and MSIX) instructions and the observability map. The backup and
restore tooling is real (`scripts/backup-postgres.ps1`, `scripts/restore-postgres.ps1`,
`scripts/restore-drill.ps1`) and the rehearsal (QB-28) exercises it end to end.

## Deliverables

| Area | What was delivered |
|---|---|
| Deployment runbook | How to deploy the web host (configuration, the DML-only role, the key ring, the ports), how to publish the desktop client and how to enrol the first device. |
| Backup and restore | The backup command, the SHA-256 manifest, the restore into a disposable database, the drill, the retention and the "restore is not a rollback" rule. |
| Credential rotation | How to rotate the database password, the Data Protection key ring and the device enrolment, and what each rotation invalidates. |
| Device procedures | A lost or stolen device (revoke it), a retired device (wipe the sandbox), a device that fell behind (`RESYNC_REQUIRED`), a device with a stuck queue and a device that must be re-enrolled to another business. |
| Failure procedures | A failed schema migration (the device refuses to start, the data stays), a corrupted device database (quarantine, re-initialise, re-sync) and a full server disk. |
| Packaging | The unpackaged build (the release workflow publishes it) and the MSIX configuration (the manifest identity, the publisher, the version stamping). |
| Observability | What the server logs (the correlation id, the typed failures, the audit feed), what the device writes (the startup report and the API-call log), the health endpoint and the metrics that matter (the pending queue, the conflicts, the feed revision). |
| CI | The build, test, secret-scan and bundle-check pipelines (QB-26) publish the same checks the rehearsal runs locally. |

## Decisions recorded

- **D-53** — operational surface (QB-27): the runbooks live next to the deployment document (one place an
  operator looks), the backup/restore tooling is scripted and rehearsed rather than described, the
  observability map names the exact artifacts (the server correlation id and audit feed, the device
  startup report and API-call log) and every procedure is written so that it never destroys business
  data: the device refuses to start on an unknown schema, the restore drill uses a disposable database and
  the device reset wipes the sandbox only.
