## Task 18 — signed native package

`QtsBilling.DataImport/NativePackageReader.cs` validates the manifest schema, mapping version, target
schema, batch, target business, effective date, capture time and exact resource set before rows are
read. Every resource is bounded, path-confined, hash/count/length checked and staged from the same
bytes that were hashed. Sensitive fields are rejected without echoing their values.

`NativePackageTests` **5/5**:

- `T18_01` — missing, altered and undeclared files refused.
- `T18_02` — traversal, absolute, case-colliding and linked paths refused.
- `T18_03` — nested credential/card fields never reach the report.
- `T18_04` — mutation between validation and apply blocks the digest.
- `T18_05` — preview identifies the exact resources and target business.

A source-era manifest (`schemaVersion: 0`, unsupported target schema) is rejected with
`MANIFEST_SCHEMA_UNSUPPORTED` and `MANIFEST_TARGET_SCHEMA_UNSUPPORTED`; it is never coerced to the
current schema. This is `NativeBoundaryTests.T02_02`.

## Task 19 — atomic native import

`NativeImportWriter` writes masters and approved openings in one transaction. Every external identity
maps to one immutable `ExternalRecordLink`; a repeated identical body reuses the target, while a
changed body or target is a conflict. Posted state is never upserted. Openings, journal lines, stock
movements/balances and party open items are committed together; a failure leaves no domain row or link.

`NativeImportWriterTests` **6/6** against real PostgreSQL:

- `T19_01` — an interrupted import leaves no domain rows or links.
- `T19_02` — a rerun reuses targets and leaves the journal and stock unchanged.
- `T19_03` — foreign business, changed body and native-key collision are refused.
- `T19_04` — opening detail ties to the general ledger, stock detail and party open items.
- `T19_05` — a mid-way database rejection leaves no partial rows.
- `T19_06` — a control-total mismatch is refused before any write commits.

## Task 20 — canonical signed reconciliation

`NativeReconciliationBuilder` compares the approved package with the persisted target using one
canonical body and one timestamp: exact per-resource counts and identity digests, aggregate/party/
ledger/account comparisons and AR/AP/inventory control totals. The verifier enforces tenant
consistency, SHA-256 provenance fields, report schema head, exact target/batch/exception binding and
freshness.

Owner approvals are separately signed and bound to the report `reportSha256`, exception id, reason,
approver and timestamp. Financial exceptions are non-waivable. A stale, unrelated or unsigned approval
cannot admit the report.

`ReconciliationTests` **5/5** cover canonical-body/timestamp/exception/approval tampering, equal counts
with wrong totals or tenant, approval A not covering new exception B, financial exceptions, unsigned
unknown/wrong-key reports and authenticated round-trips. `T20_06` imports a real package, builds the
exact report, verifies digest/HMAC and reproduces the identical canonical bytes on a rerun.

## Task 21 — signed production admission

`scripts/qb30-cutover.ps1` separates read-only **Admission** from **Execute**. The manifest
`schema: qts-production-approval-v2` is HMAC-SHA256 signed and binds environment, server, database,
business ids, approved device ids, release SHA, migration head, package/report/drill/G7 hashes,
approved exceptions and expiry. One owner codeword is read from `QTS_CUTOVER_CODEWORD` and checked as
its SHA-256 against the manifest; there is no second caller-supplied comparison codeword.

Admission performs **44 gates, 0 mutations**. Before the first write, Execute re-verifies the manifest
and every evidence hash. The ordered effects are:

`backup → host/health → native import → reconcile → verify → owner reset → smoke → final integrity`

A nonzero import stops after `backup,host,import`; reconciliation, verify, identity reset and smoke
are never reached. A tampered report hash, missing device, wrong server/database or missing manifest
stops with zero mutations.

`ProductionAdmissionTests` **8/8** run `scripts/Test-ProductionAdmission.ps1` with controlled doubles:

- `T21_01` — a failed first gate stops before any mutation.
- `T21_02` — one caller codeword without a signed manifest authorizes nothing.
- `T21_03` — an approval for server A cannot execute database B.
- `T21_04` — a nonzero import stops before reconciliation/reset/smoke.
- `T21_05` — valid admission is read-only and has no production authority.
- `T21_06` — valid execution uses approved evidence and the ordered steps exactly once.
- `T21_07` — tampered/incomplete manifests are refused without mutation.

The harness requires PowerShell 7. A missing `pwsh` fails the test instead of skipping it. Ordinary
tests never execute the cutover against a real target.
