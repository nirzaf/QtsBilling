# QB-01 — Establish clean solution boundaries without deleting WinForms yet

**Status: DONE.** WinForms is retained (deletion is QB-29, gated); the web host no longer depends on it.

## Changes

| File | Change |
|---|---|
| `QtsWebApp/QtsWebApp/QtsWebApp.csproj` | `net10.0-windows` → `net10.0`; removed `ProjectReference` to the WinForms `QtsBilling` project; added an explicit `ProjectReference` to `QtsServices` (server-side application services, temporarily Mongo-backed until QB-03…QB-13 replace them). |
| `QtsWebApp/QtsWebApp.Client/QtsWebApp.Client.csproj` | `net10.0-windows` → `net10.0` (browser build must not be Windows-specific). |

The solution still contains `QtsBilling` (WinForms) so the legacy desktop app remains recoverable.

## Evidence

```text
dotnet build QtsWebApp\QtsWebApp\QtsWebApp.csproj -c Debug   → Build succeeded, 0 warnings, 0 errors
QtsWebApp\QtsWebApp\bin\Debug\net10.0\QtsWebApp.dll          → exists (plain net10.0 output)
QtsWebApp\QtsWebApp.Client\bin\Debug\net10.0\wwwroot\_framework → WASM bundle produced
dotnet build QtsBilling.sln -c Debug                          → Build succeeded, 0 errors
```

Grep verification: no references to `QtsBilling.csproj` remain outside the solution file itself, and no
Windows-only API usage exists in the web host or client.

## Known interim state (spec QB-01 acceptance explicitly allows this, as a recorded release blocker)

`QtsWebApp.Client` still references `QtsServices`; the browser output therefore still ships database
client assemblies (`_framework/DnsClient.*.wasm`, MongoDB driver assemblies were observed in the build
output). This is exactly finding F-19 and is removed by QB-15. **No interim browser build may be
published** until QB-15 lands.
