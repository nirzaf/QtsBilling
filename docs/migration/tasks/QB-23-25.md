# QB-23 / QB-24 / QB-25 — Historical data import (export, transform, load, reconciliation)

**Status: BLOCKED — the work needs an input that does not exist in this repository or on this machine.**
The three tasks form one chain (a read-only source inventory → a deterministic transform and load → a
signed reconciliation report and the account-reset plan). The chain is fully specified below and ready to
execute, but two of its inputs are missing:

1. **There is no legacy source to read.** The legacy WinForms client and the legacy BSON entities were
   removed from the repository with QB-29 (the user's codeword), so the *field mapping* of the legacy
   collections is no longer in the source tree, and no legacy MongoDB instance is reachable from this
   machine (`QTS_MONGODB_REMOTE` is unset).
2. **A wrong mapping would corrupt money silently**, which the specification forbids ("No silent data
   repair... ambiguous or unmappable legacy records enter an explicit reconciliation report"). Writing a
   guessed mapping and calling it done would be exactly that failure mode.

Everything that does **not** depend on the source is finished and verified: the PostgreSQL target schema,
the `legacy_identifier_map` table, the identifier rules, the audit and the reporting surfaces, and the
operational runbooks for a rehearsal (QB-27/QB-28).

## What the chain must do (the specification, ready to build)

| Task | Required behaviour | Gate |
|---|---|---|
| QB-23 inventory | A **read-only** connection to the legacy source: list every collection with its document count, the field names it uses and a sample document per collection, plus the source commit/build. Nothing is written to the source, and no credential is stored in the repository. | A reachable legacy instance (or an exported snapshot) and the source commit. |
| QB-24 transform and load | A **deterministic** transform: the same source document always produces the same target rows (no clock, no random, no dictionary-order dependence), the money keeps its exact scale, the identifiers are mapped through `legacy_identifier_map` (source collection + legacy id → target id) so a re-run is idempotent, and a record that cannot be mapped is **not** silently dropped: it goes into the reconciliation report. | The field mapping (from QB-23's inventory) and a target schema that is migrated. |
| QB-25 reconciliation and reset | A report that states, per collection, the source count, the imported count, the skipped count and the reason for every skip, with a checksum of the report; the report is signed (a signature over the report hash, key from the environment). The account-reset plan lists exactly which accounts are reset, which credentials are invalidated and the order of the cutover steps. | The import has run at least once against a copy of the source. |

## What is already in place

- The target schema: `QtsBilling.Persistence.Postgres` (38+ tables, the balanced ledger, the inventory
  movements, the immutable sales) with the append-only and the optimistic-concurrency guards.
- `legacy_identifier_map` (source collection, source id, target id) so a re-run never duplicates a record.
- The audit feed and the typed failures, so the import can be observed and explained afterwards.
- The read-only PostgreSQL role (`scripts/provision-postgres-roles.ps1`) and the backup/restore tooling, so
  the import can be rehearsed against a disposable database before it touches the real one - the same
  pattern the rehearsal uses (QB-28).

## Decisions recorded

- **D-55** — historical import is gated on the legacy source (QB-23/24/25): the import chain is
  specified and the target side is ready, but the chain is not started without (a) a reachable read-only
  legacy instance or an exported snapshot and (b) the legacy field mapping. The legacy model was removed
  from the repository with QB-29 before the tooling existed, and a guessed mapping would risk the silent
  data repair the specification forbids. The gate is explicit rather than hidden in a half-finished tool.

- The pilot data load (QB-28) and the production cutover (QB-30, gated behind the cutover codeword).
