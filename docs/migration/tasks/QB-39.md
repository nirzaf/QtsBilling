# QB-39 — The cutover is a fail-closed, environment-bound admission (F01/F02/F05)

**Status: DONE (the two modes behave as specified; the wrong codeword and a mismatched target stop the run).**

This is task 21 of the *SMB Completion and Production Hardening* specification. It closes the
critical findings **F01** and **F02** and the high finding **F05**.

## What was wrong

| Finding | Defect | Now |
|---|---|---|
| **F01** | The script took the codeword **and** the expected codeword as caller-supplied arguments — a caller could accept its own codeword — and the comparison was a plain string comparison that leaked the length. | The codeword comes from the **environment** (`QTS_CUTOVER_CODEWORD`) and is compared with the presented value in **constant time**. The script has no argument that can accept a codeword. A mismatch stops the run before anything is touched. |
| **F01** | The read-only admission and the approved write were the same run. | Two strictly separated modes: **`-Mode Admission`** (read-only, no codeword, changes nothing) and **`-Mode Execute`** (the approved write, codeword required). |
| **F02** | The backup, the SQL, the command line tool and the HTTP target were not bound to one environment. | The script derives the database, the host, the port and the user from `QTS_POSTGRES_CONNECTION` and **verifies that the container serves that very database** before it does anything; the backup manifest must name the same database. A mismatch is a failed gate, not a warning. |
| **F02** | A skipped import counted as a pass. | In the execute mode a missing snapshot or a missing transformation is a **failed** gate: "a skipped import is not a pass". |
| **F02** | The device was **upserted** by the script — an automatic enrolment is not an approval. | The script never enrols a device. It verifies that the **approved** device list is enrolled and active, and it fails when no approved device was named. |
| **F05** | The stock value was not tied to the balances. | A new integrity gate ties the sum of the movement values to the value on hand of every balance — the same tie the quantity already had. |

The script still never deletes anything and never rolls back to the legacy system: a failed gate means
*stop and fix forward*, and the import is idempotent.

## Evidence (live, against the development environment)

| Run | Result |
|---|---|
| `-Mode Execute` with a **wrong** codeword | **stops at the codeword gate**, exit code 1, nothing else is touched. |
| `-Mode Execute` with the correct codeword | **20 gates, 0 failed**, exit code 0: the environment binding, the backup with its manifest, the health, the schema (0 pending migrations), the idempotent import, the signed reconciliation, the identity reset, the approved device fleet, the smoke, the ledger/stock/value/tenant/numbering/payment integrity checks and the no-legacy-dependency check. |
| `-Mode Admission` (read-only, no codeword) | **20 gates, 0 failed** with the approved exceptions and the approved device list. Without them it refuses (2 failed gates) — an admission without the approvals is not a pass. |

The evidence file of the earlier rehearsal is `docs/migration/tasks/qb30-evidence.txt`; the new run
writes the same checklist to the console and the reconciliation report to
`backups/cutover-reconciliation.json`.

## Decisions recorded

- **D-68** — the admission and the cutover (task 21): the read-only admission and the approved write
  are separate runs. The codeword comes from the environment and is compared in constant time — the
  script has no argument that can accept a codeword. Everything is bound to one environment: the
  database, the backup, the migration state, the command line tool and the HTTP target must name the
  same database, or the run stops. A skipped import is a failed gate, and the script never enrols a
  device: an enrolment is an approval, not a side effect.
