# QB-39 — The cutover is a fail-closed, environment-bound admission (F01/F02/F05)

**Status: DONE, after a correction.** The first version of this slice was reviewed and two defects were
found in it: the "read-only" admission was not read-only, and the execution did not stop at a failed
gate. Both are fixed and proven by a test.

## The two defects that were found

| Defect | What it actually did | Now |
|---|---|---|
| **The "Admission" was not read-only** | it created a backup, started a **Production**-configured application host, and sent a **password-reset request** and a **login** request — the reset request invalidates the owner's ability to sign in and both write audit rows. | The admission creates **no backup**, starts **no host** and sends **no auth request**. It only reads: the environment binding, the reachability, the schema state, the reconciliation evidence, the identity and device state, the integrity ties, and the **latest existing backup** (its manifest and its hash). A missing backup is a failed gate — the admission never creates one. |
| **A failed gate did not stop the run** | the gates were collected and only inspected at the very end, so a failed **backup**, **health** or **schema** check still reached the **import**. The documentation claimed "it stops at the first failed gate"; the code did not do that. | Every gate is followed by `Assert-NoFailedGate`, so the run **stops at the first failed gate** — the import is reached only after the backup, the health check and the schema check have passed. |

## What the script does now

- **Two modes, strictly separated by what they may touch.** `-Mode Admission` is read-only and needs no
  codeword. `-Mode Execute` performs the cutover and needs the business owner's codeword, which is read
  from the environment (`QTS_CUTOVER_CODEWORD`) and compared in **constant time** — the script has no
  argument that can accept a codeword.
- **Fail closed.** The run stops at the first failed gate; the stop/fix-forward plan is printed and the
  exit code is 1.
- **One environment.** The database, the backup, the migration state, the command line tool and the
  HTTP target must all name the same database; the script verifies that the container serves it and
  that the backup manifest names it.
- **No silent skips.** A missing snapshot or transformation is a failed gate ("a skipped import is not
  a pass").
- **No automatic enrolment.** The script verifies that the **approved** device list is enrolled and
  active, and fails when no approved device was named. An enrolment is an approval, not a side effect.
- **Nothing is deleted and nothing is rolled back.** A failed gate means stop and fix forward; the
  import is idempotent.

## The two further defects that were found (and fixed)

| Defect | What it did | Now |
|---|---|---|
| **The Execute path used a variable before assigning it** | the smoke's sign-in read $email **before** the identity step assigned it, so the login body carried an empty address. The run then failed at the smoke — **after** the import had already run. | The address is assigned before it is used (and it is a parameter, not a literal in the middle of the script). The Execute path now completes with **every gate passed** (T5a). |
| **CI never ran the script** | the cutover safety was unverified on every build. | The CI now installs the PostgreSQL client, applies the migrations to the test database and runs scripts/qb39-cutover-safety.ps1 against it. The script and the backup work both through the container (development) and straight against a reachable server (-SqlMode Psql, the CI). |

## The proof

`scripts/qb39-cutover-safety.ps1` exercises the paths that matter and asserts the *absence* of side
effects (12 assertions, all green):

| Case | What it proves |
|---|---|
| T1a | the admission creates **no backup file** (the dump count is unchanged). |
| T1b | the admission starts **no application host** (the host log is never created). |
| T1c | the admission sends **no password-reset and no login request** — the audit trail of the database is byte-identical before and after. |
| T2a/T2b | a mismatched environment **stops** the admission, and the environment gate is the one that failed. |
| T3a/T3b | a failed gate **stops the execution before the import** — the import gate is never reached. |
| T4a–T4d | the import is reached **only after** the backup, the health check and the schema check have passed. |
| T4e | the script itself declares the gates in that order (the read-only admission checks the schema too, so the last occurrence of each gate is the one that matters). |
| T5a | the **Execute path completes with every gate passed** — the whole approved cutover, end to end, not only its failure paths. |

# the proof (it needs a reachable PostgreSQL and the container that serves it)
$env:QTS_POSTGRES_CONNECTION = "Host=localhost;Port=5433;Database=qtsbilling;Username=qtsbilling;Password=..."
$env:QTS_CUTOVER_SNAPSHOT = "<the frozen snapshot>"
$env:QTS_CUTOVER_ROWS = "<the transformed rows>"

$env:QTS_CUTOVER_APPROVED_EXCEPTIONS = "<the approved exception ids>"

## Decisions recorded

- **D-68** — the admission and the cutover (task 21): the read-only admission and the approved write
  are separate runs, and the admission touches **nothing** — no backup, no host, no auth request. The
  codeword comes from the environment and is compared in constant time; the script has no argument that
  can accept a codeword. Every gate is fail-closed: the run stops at the first failure, so a failed
  backup, health or schema check can never reach the import. Everything is bound to one environment, a
  skipped import is a failed gate, and the script never enrols a device: an enrolment is an approval.
- **D-69** — the side-effect proof (task 21): a mode that is called read-only is proved to be
  read-only by asserting the *absence* of side effects (no new dump, no host log, an unchanged audit
  trail), and the fail-closed order is proved by asserting that the import gate is never reached after
  a failed gate. The claim and the code must agree, and the claim is checked by a test.
