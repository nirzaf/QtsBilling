# QB-39 — fail-closed, environment-bound cutover admission (superseded)

**Status: SUPERSEDED by Task 21.** The history below records why the original slice was corrected;
the current implementation and evidence are in [QB-45](QB-45.md).

## What Task 21 changed

- The caller-supplied codeword **pair** is gone. One owner-held codeword is compared as a SHA-256
  against a signed environment approval manifest (`schema: qts-production-approval-v2`).
- The manifest binds the environment, server, database, business ids, approved device ids, release
  commit, migration head, package/report/drill/G7 hashes, approved exceptions and expiry.
- Every evidence hash is re-checked immediately before the first write; a changed file stops the run.
- Admission remains read-only: it creates no backup, starts no host and sends no auth request.
- Execution remains fail-closed and ordered: backup → host/health → native import → signed
  reconcile/verify → owner reset → smoke → final integrity.

## Current proof

`TestQtsBilling/Operations/ProductionAdmissionTests.cs` runs
`scripts/Test-ProductionAdmission.ps1`, which dot-sources the production script and replaces every
external effect with a controlled double. It proves:

- a failed first gate performs no mutation;
- two matching caller-supplied codewords without a signed manifest authorize nothing;
- an approval for server A cannot execute database B;
- a tampered report hash or missing approved device is refused;
- a nonzero import exit stops before reconciliation, identity reset or smoke;
- a valid admission is read-only and does not imply owner production authorization;
- a valid execution runs each effect exactly once in the approved order.

The harness requires PowerShell 7. A missing `pwsh` fails the test rather than skipping it. Ordinary
tests never execute the cutover against a real target.

## Historical defects (fixed before Task 21)

The first version of this slice collected gates and only inspected them at the end, so a failed
backup/health/schema gate could still reach the import; and the "read-only" admission actually
created a backup, started a host and sent auth requests. Both were corrected, and the Task 21
harness retains the absence/fail-closed assertions. The original evidence remains in Git history.
