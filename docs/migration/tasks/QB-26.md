# QB-26 — Focused tests and CI pipelines

**Status: DONE (CI and release verification run against disposable PostgreSQL).** CI builds the web host
and WASM client on Linux, runs PostgreSQL/API, SQLite and migration tests, provisions a DDL migration
owner and a separate DML-only runtime role, checks the WASM bundle and secret/encoding scan, and builds
the Windows desktop client on a Windows runner with the MAUI workload. Release verifies the same server
gates before publishing versioned Windows/Linux server and Windows desktop assets.

## Deliverables

| Area | What was delivered |
|---|---|
| CI pipeline | `.github/workflows/ci.yml`: server + client build, PostgreSQL/API tests, SQLite tests, migration tests, least-privilege role checks, cutover safety, secret/encoding scan, WASM assembly inspection, and a separate Windows desktop build. |
| Release pipeline | `.github/workflows/release.yml`: the verify job runs before any release asset job; the version is derived from the tag, and the server and desktop assets are packaged with checksums. |
| Test suites | The PostgreSQL/API suite uses a random `qts_test_…` database, migrations run as `qts_migrator`, and the API host connects as `qts_app`; the SQLite and migration suites remain service-independent. |
| Secret and encoding scan | `scripts/secret-scan.ps1` scans tracked text files for credentials and the double-encoded UTF-8 byte sequence; documented disposable fixtures remain allowlisted. |
| WASM guard | `scripts/verify-wasm-bundle.ps1` rejects PostgreSQL, Npgsql, EF relational, and OpenIddict server assemblies in the published browser bundle. |
| Local parity | `scripts/qb28-rehearsal.ps1` runs the same steps locally, so a developer sees the pipeline result before pushing. |

## Evidence

| Check | Result |
|---|---|
| Full solution build | `dotnet build QtsBilling.sln --no-restore -c Release` succeeds with zero warnings and errors. |
| Full solution tests | 138 PostgreSQL/API, 34 SQLite, and 9 migration tests pass (181 total) against PostgreSQL 18 with the DML-only role as the API runtime. |
| Least-privilege gate | Migrations run as the non-superuser owner; the runtime role can query products and is refused `CREATE`, `ALTER`, `TRUNCATE`, `CREATE TRIGGER`, and `DROP`. |
| WASM guard | Release publish passed; 195 framework files were checked and none contained forbidden server assemblies. |
| Secret and encoding scan | 378 tracked files scanned; no unallowlisted secrets or double-encoded UTF-8 sequences. |

## Decisions recorded

  distinct DDL migration role and DML runtime role; SQLite and migration unit suites remain isolated;
  release assets are built only after verification and only from a `vMAJOR.MINOR.PATCH` tag.
