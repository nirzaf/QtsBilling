# QB-26 — Focused tests and CI pipelines

**Status: DONE (pipelines in place and green locally).** Two GitHub Actions pipelines guard the
repository: **CI** builds the web host and the WASM client on Linux, runs the two test suites (the domain
and contract tests plus the device-store tests, neither of which needs an external service) and builds the
Windows desktop client on a Windows runner with the MAUI workload; **Release** publishes the server for
`win-x64` and `linux-x64` and the desktop client for `win-x64` when a `vMAJOR.MINOR.PATCH` tag is pushed.
The static secret scan (`scripts/secret-scan.ps1`) is part of the pipeline and of the rehearsal.

## Deliverables

| Area | What was delivered |
|---|---|
| CI pipeline | `.github/workflows/ci.yml`: the server + client build, the two test suites, the secret scan, and the desktop build on a Windows runner. The MAUI workload is installed only where it is needed (Linux never restores it). |
| Release pipeline | `.github/workflows/release.yml`: the version is derived from the tag, the server is published self-contained for Windows and Linux, the desktop client for `win-x64`, and the assets are packaged with their checksums. |
| Test suites | `TestQtsBilling` (domain and contracts) and `QtsBilling.Persistence.Sqlite.Tests` (the device store, the capture rules, the sync window, the conflicts and the cursor) - both run without a database, a MongoDB or a network. |
| Secret scan | The repository-wide scan with the documented development fixtures allowlisted; it fails the pipeline on anything new. |
| Local parity | `scripts/qb28-rehearsal.ps1` runs the same steps locally, so a developer sees the pipeline result before pushing. |

## Decisions recorded

- **D-52** — pipeline scope (QB-26): the pipelines build what each runner can build (the server, the
  WASM client and the libraries on Linux, the desktop client on Windows with the MAUI workload) and run
  the two test suites that need no external service, so a pull request is verified without a database, a
  MongoDB or a network. The secret scan is part of the gate, and the release pipeline only publishes from
  a `vMAJOR.MINOR.PATCH` tag.

## Not included (tracked)

- Coverage reporting and a coverage gate (the test projects collect coverage; the threshold is not
  enforced yet).
- The integration tests against a live PostgreSQL in the pipeline (the rehearsal covers them locally).
