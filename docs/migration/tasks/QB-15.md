# QB-15 — Remove web client database dependencies

**Status: DONE for the current browser surface — the WebAssembly bundle no longer contains any database
driver, Mongo type or server credential.**

## Deliverables

| Change | Detail |
|---|---|
| Project references | `QtsWebApp.Client.csproj` references `QtsBilling.Contracts` only; the `QtsServices` (MongoDB/BSON) reference is gone. |
| DI | `Program.cs` registers a single `HttpClient` (same-origin base address) plus `ICustomerApiClient`/`IAccountApiClient`; no service talks to a database. |
| Pages | Customers page rewritten against the typed client (search, paging, inline edit, deactivate, add dialog); new Login page drives sign-in/enrolment; layout shows the signed-in user and sign-out. |
| Contracts | Shared DTOs + `ApiException` mapping so failures surface as actionable messages rather than exceptions. |
| Server | The web host itself no longer references `QtsServices` either; it hosts the API and the Blazor app on PostgreSQL. |

## Evidence — browser bundle contents

```text
QtsWebApp\QtsWebApp.Client\bin\Debug\net10.0\wwwroot\_framework
  Mongo*            → none
  DnsClient*        → none   (F-19 evidence previously listed DnsClient.*.wasm)
  Npgsql*           → none
  EntityFramework*  → none
  QtsServices*/QtsModels* → none
  wasm assets: 208 (framework + UI only; System.Data.* are BCL framework assemblies, not drivers)
```

Runtime verification of the API-backed UI is covered by the QB-05/QB-06 request evidence; the pages
themselves are the only browser-reachable surface and contain no connection string, key or secret.

## Notes / follow-ups

- `QtsBilling` (WinForms) intentionally still references `QtsServices` — its removal is gated (QB-29).
- As further pages are migrated (sales, invoices, reports), they must follow the same rule: typed API
  client only. A bundle check belongs in CI (QB-26) so a regression fails the build.
