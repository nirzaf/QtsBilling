# QB-13 — Financial and operational reports from authoritative facts

**Status: DONE (verified live on PostgreSQL 18.6).** Statements are derived per request from the posted
journal and the inventory movement ledger: there is no stored balance to mutate, no materialized report
service, and provisional offline captures are excluded by construction because only posted facts are read
(spec §3.9, F-14).

## Deliverables

| Area | Contents |
|---|---|
| Authoritative-only balances | No mutable Assets/Liabilities/Equity CRUD exists in the host (the legacy `BalanceSheetService` belonged to the deleted WinForms layer and never had a counterpart here). Account CRUD manages chart-of-accounts *master data*; every figure in a statement comes from posted `journal_lines` joined to posted `journal_entries`. Legacy saved balance sheets would remain archived for comparison only; none were reachable (MongoDB unreachable — QB-23/24 blocked) so nothing is imported. |
| Balance sheet | `GET /api/v1/reports/balance-sheet?asOf=&currency=` — asset accounts (debit-normal) and liability/equity accounts (credit-normal) as of a cut-off, plus `currentEarnings` (revenue − expenses) presented as part of equity since revenue/expense accounts are not closed to equity by any stored step. Response carries `balanced` (assets = liabilities + equity within rounding) and echo of the business id. |
| Profit and loss | `GET /api/v1/reports/profit-and-loss?from=&to=&currency=` — revenue (credit − debit) and expense (debit − credit) sections with net profit; default window is the last year ending today; `from > to` is refused with `400 VALIDATION_FAILED`. |
| Stock summary | `GET /api/v1/reports/stock-summary?asOf=&locationId=&currency=` — per location/variant quantity and value from the **movement ledger** (`Σ quantity_delta`, `Σ quantity_delta × unit_cost`, honest cost snapshots) with last-movement timestamps and totals; an unknown/foreign location id is refused with `404 NOT_FOUND`. |
| Cash summary | `GET /api/v1/reports/cash-summary?from=&to=&currency=` — opening balance, debits, credits and closing balance for the standard cash (`1000`) and bank (`1010`) accounts, computed from posted lines; provisional drawer money is absent because it is never posted. |
| Sales summary | `GET /api/v1/reports/sales-summary?from=&to=&currency=` — posted sales count and amount breakdown plus confirmed money per payment method; unconfirmed/voided money never counts and provisional device captures are not part of the response (`includesProvisional: false` on every statement). |
| Scoping and filters | Every query is scoped by the `BusinessId` from the signed-in membership; every response echoes the business id so scoping is auditable. Only the business base currency can be reported — any other `currency` value is refused. Date slicing is exact (`EntryDate` for the ledger, `OccurredAtUtc` for stock/money timestamps). |
| Closed periods | Reports read posted facts only and never mutate them; period closure gates posting at write time (QB-07), so closed periods are reported identically and immutably. |

## Decisions recorded

- **D-42** — derived statements: balance sheet/P&L/cash/stock/sales are computed per request from posted
  journal lines and inventory movements; no stored balance CRUD, no materialized reports; responses echo
  the business id, only the base currency is reportable, provisional offline money is excluded by
  construction, and closed periods are read-only facts. Documented boundary: the GL inventory account
  (`1200`) reflects posted cost entries (COGS on sales) only — supplier settlement/inventory capitalization
  posting for goods receipts is a deliberate follow-up, so stock valuation is reported from the movement
  ledger while the balance sheet reports the ledger as-is.

## Not included (tracked per task)

- A business-intelligence platform or materialized reporting service — explicit non-goal of QB-13.
- Currency translation/presentation in non-base currencies — refused rather than approximated.
- Provisional offline cash/sales reconciliation is a device-side concern (QB-19/20); the server reports
  authoritative posted facts only and labels every statement `includesProvisional: false`.
