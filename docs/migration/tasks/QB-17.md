# QB-17 — Device-local SQLite persistence

**Status: DONE (library, schema, migrations, store and tests).** The device-local store now exists as a
separate .NET library, `QtsBilling.Persistence.Sqlite`, with its own EF Core migration history, checked
scaled-decimal converters, a single-writer WAL policy, a durable outbox that is never discarded by a cache
rebuild, and a startup sequence that refuses to run against an unknown or newer schema. The library is
host-agnostic: the MAUI host will consume it through `AddQtsSqliteLocalStore` once the `maui-windows`
workload is available (D-25). No web/browser component may reference it.

## Deliverables

| Area | What was delivered |
|---|---|
| New project | `QtsBilling.Persistence.Sqlite` (`net10.0`) on `Microsoft.EntityFrameworkCore.Sqlite` 10.0.13 with the `Design` package (private assets) for authoring migrations. It references only `QtsModels` (provider-neutral value objects) — no Npgsql, no MongoDB, no web host, no `QtsBilling.Contracts`. |
| Local schema | The specification 4.2 tables with exact snake_case names: `device_profile`, `cached_products`, `cached_customers`, `cached_stock`, `cache_tombstones`, `local_sale_drafts`, `local_sale_lines`, `local_cash_movements`, `outbox_operations`, `inbox_receipts`, `sync_state`. Primary keys, indexes and `CHECK` constraints (cash-only payments, lifecycle states, non-negative money, positive quantity, non-negative attempts, positive payload version) are enforced by the database, not only by code. |
| Cache vs. pending separation | One WAL database file holds two clearly separated table groups: **discardable cache** (`cached_*`, `cache_tombstones`) and **durable pending** (`local_sale_*`, `local_cash_movements`, `outbox_operations`, `inbox_receipts`, `device_profile`, `sync_state`). `RebuildCacheAsync` deletes only the cache group. A single file is deliberate: an offline capture must write the draft, its lines, the cash movement and the outbox row in **one** transaction, which two files could not provide. |
| Checked scaled decimals | `LocalValueConverters` maps `decimal` to scaled `long` through `QtsModels.ValueObjects.ScaledDecimal`: money at scale 10,000, quantity at scale 1,000,000. Extra precision (`0.00001` money) and 64-bit overflow are **rejected** (`InvalidOperationException` / `OverflowException`), never truncated or saturated, and no column is `REAL`/`float`/`double`. Values are dry-run before the capture transaction starts, so a rejection never leaves a half-written sale. |
| Two independent migration histories | The device file carries its own `__EFMigrationsHistory` (`20261019141355_InitialLocalStore`, `20261019141709_AddSaleLineNonNegativeChecks`); the PostgreSQL history in `QtsBilling.Persistence.Postgres` is untouched (0 changed files). The v2 migration rebuilds `local_sale_lines` to add the non-negative money checks, which exercises the upgrade path against real pending rows. |
| Startup before sync | `SqliteLocalStore.InitializeAsync` runs before any sync work: `PRAGMA quick_check` (corruption blocks startup, nothing is deleted or rebuilt), compatibility check (an unknown migration id or a newer `user_version` blocks startup and leaves the file untouched), `PRAGMA journal_mode=WAL`, a `VACUUM INTO` pre-migration snapshot, the pending migrations, `PRAGMA user_version`, and finally the recovery of operations that were in flight when the device stopped. |
| Single writer, crash-safe commits | All writes pass through one in-process write gate (`SqliteWriteGate`); every connection enables `foreign_keys=ON`, `synchronous=FULL` and `busy_timeout=5000`; WAL keeps readers unblocked. Capture and receipt application are single transactions. |
| Durable outbox | `outbox_operations` stores the canonical payload, its SHA-256 fingerprint, the payload version, the attempt count and the next attempt time. Replaying the same operation id with the same payload is a no-op; a different payload raises `SqliteSameKeyDifferentPayloadException`. Acknowledged/rejected rows are retained for review and are never deleted automatically. |
| Receipts | `ApplyReceiptAsync` commits the inbox receipt, the outbox state, the draft/cash state and the error code in one transaction. The same receipt replayed is a no-op; a conflicting outcome raises `SqliteReceiptConflictException`. `Posted`/`AlreadyPosted` acknowledge, `TransientRetry` keeps the operation pending, everything else rejects — and a rejected sale keeps its money rows for review. |
| Scoped device services | `AddQtsSqliteLocalStore(SqliteLocalStoreOptions)` registers the scoped `SqliteLocalStore`, the singleton write gate, the EF context factory with the pragma interceptor, and `TimeProvider`. The host supplies the private data-directory path (`FileSystem.AppDataDirectory` on MAUI). |
| Tests | New `QtsBilling.Persistence.Sqlite.Tests` (xUnit 2.9.3) with **20 temp-file tests** — every test uses a real SQLite file, closes and reopens the provider to simulate crash/restart, and deletes the directory afterwards. |

## Legacy items mapping

| Legacy concern | Resolution |
|---|---|
| No device-local store existed; the desktop client was WinForms against a central database | The device store is a new, self-contained library with its own schema, migrations and retention rules. |
| Money as `decimal`/`double` in local caches | Only checked scaled integers cross into SQLite; `REAL` is impossible in the model. |
| Implicit "delete everything on logout" | Only the cache group is discardable. Pending sales, cash movements, outbox rows, receipts, device profile and sync cursors survive cache rebuilds and are only removed by an explicit operator/retirement action. |
| Schema drift on upgrade | Unknown migration ids or a newer schema version block startup; a pre-migration snapshot is taken before any migration runs. |

## Decisions recorded

- **D-46** — device-local store shape (QB-17): one WAL SQLite file per device with two separated table
  groups (discardable cache vs. durable pending money/outbox/receipts/sync state) so that an offline capture
  can commit draft + lines + cash + outbox atomically while a cache rebuild can never touch money rows.
  Money/quantity cross the boundary only as checked scaled `INTEGER` values (money ×10 000, quantity
  ×1 000 000) with precision loss and overflow rejected instead of truncated. The device file keeps its own
  EF migration history, completely independent of the PostgreSQL history. Startup blocks on a failed
  integrity check, an unknown migration or a newer schema version, and takes a `VACUUM INTO` snapshot before
  applying migrations. The file is device-local and disposable only for the cache group; pending operations
  and their idempotency keys are retained until the server acknowledges them (OPEN-8 remains open for
  at-rest encryption; the interim policy is OS-level protection inside the app sandbox).

## Not included (tracked)

- The .NET MAUI host and its sync coordinator (QB-18/QB-19/QB-20) — blocked by the missing `maui-windows`
  workload (D-25). The library is host-agnostic and unit-tested, but no MAUI binary consumes it yet.
- Server-side sync endpoints and change feed (QB-20/QB-21).
- Final at-rest encryption for the device file (**OPEN-8**): the implementation deliberately ships without
  SQLCipher and relies on the app sandbox plus OS-level protection; the policy is explicit in
  `docs/migration/deployment.md`.
- Copying the central PostgreSQL tables to the device, and any SQLite access from the web application
  (specification non-goals).
