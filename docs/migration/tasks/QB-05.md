# QB-05 — Typed, authenticated API on the existing web host

**Status: DONE for the first vertical slice (auth + customers + health). Further module endpoints land
with their own tasks (QB-07+).**

The API lives in the same ASP.NET Core host as the Blazor app (single deployment, same-origin cookies),
so no extra service or CORS surface is introduced.

## Deliverables

| Area | Contents |
|---|---|
| Versioned routes | `/api/v1/auth/*`, `/api/v1/customers/*`, `/api/v1/health`; route groups carry tags for OpenAPI. |
| Contracts | `QtsBilling.Contracts` DTOs shared by server, browser client and (later) MAUI; `ContractJson` options keep one wire shape everywhere. |
| Errors | RFC 9457 ProblemDetails everywhere, always with a stable `code` (`ApiErrorCodes`), plus per-field `errors` for validation failures (`VALIDATION_FAILED`). |
| Correlation | `CorrelationIdMiddleware` sets/echoes `X-Correlation-Id` and puts it on `HttpContext.TraceIdentifier`; responses carry `traceId`. |
| Auth | Cookie scheme with 401/403 (no redirects) under `/api`; permission policies per endpoint; tenant id resolved from `qts:business_id`. |
| Prerender support | `LocalApiHandler` rewrites the typed clients' requests to the current request origin and forwards the session cookie, so server prerender renders exactly what the browser will see. |
| Typed clients | `ICustomerApiClient`/`CustomerApiClient`, `IAccountApiClient`/`AccountApiClient` (+ `ApiHttp` error mapping to `ApiException`). |
| Observability | OpenAPI document in Development (`/openapi/v1.json`); SQL/EF logs available in Development. |
| Health | `GET /api/v1/health` → `200 {status:"ready",store:"postgresql"}`; `503 STORE_UNAVAILABLE` when PostgreSQL cannot be reached. |

## Evidence

```text
GET  /api/v1/health                                  → 200 {"status":"ready","store":"postgresql",…}
GET  /api/v1/customers            (anonymous)        → 401
POST /api/v1/auth/login           (setup pending)    → 403 {"code":"PASSWORD_RESET_REQUIRED"}
POST /api/v1/customers            (viewer role)      → 403 (permission policy)
GET  /api/v1/customers/…          (unknown)          → 404 {"code":"NOT_FOUND"}
POST /api/v1/customers            (invalid payload)  → 400 {"code":"VALIDATION_FAILED","errors":{…}}
PUT  /api/v1/customers/{id}       (stale If-Match)   → 409 {"code":"CONCURRENCY_CONFLICT"}
POST /api/v1/customers            (duplicate phone)  → 409 {"code":"DUPLICATE_PHONE"}
Responses                                            
  X-Correlation-Id + traceId on every request/response
```
